# 导入的文件挪了、改了名也能接着用

日期：2026-11-20

## 为什么做

用户自己导入的壁纸、音乐、视频，软件只记了路径。整理文件夹、改个文件名之后，「我的壁纸」里显示"找不到文件"，深度图要重新生成，歌单里的歌放不了，只能删掉重新导入。

目标：在同一个盘里挪动、改名之后，软件自己接上，用户感觉不到；自动接不上的情况，点一下就能手动接上。

## 范围

要管的路径：

- `myWallpapers[].path`
- `currentImage`、`currentImageCrop.path`、`currentVideo.path`、`currentVideo.imageAtTime`（这也是一个图片路径）
- `vinyl.playlist[].path`、`vinyl.coverPath`
- `videoOverlay.customPath`
- 深度图缓存索引 `cache_index.json`（key 是路径的哈希，条目里有 `imagePath`）

不用管：

- 元素、解锁动画：导入时已经复制到数据目录。
- 默认壁纸：软件自带，在安装目录里。
- 数据目录（userData）里的文件。

## 目标

- 同一个盘里移动、改名、换文件夹（包括整个文件夹挪走）后自动接上：列表照常显示，深度图不重算，裁剪、效果、声音这些设置都还在。
- 自动接不上时，点"找不到文件"的格子或者歌就能选文件手动接上；接上一个以后，原来同一个文件夹里其它找不到的文件按相同的相对位置顺带接上。
- 手动接上的如果是桌面上正在用的壁纸，桌面马上恢复。

## 不做 / 做不到

- 挪到别的盘、放在 FAT32 / exFAT 的 U 盘上、网络路径、ReFS 盘（Windows 的"开发驱动器"）：自动找不回，只能手动接上。
- U 盘换了盘符：不自动找，手动接上。
- 扔进回收站的：当成找不到，不会接到回收站里去。
- 这次更新之前就已经找不到的：当时没记编号，只能手动接上。
- 不复制文件，不改原文件，不在整个硬盘里搜同名文件。

## 反目标（技术上能用也算失败）

- 把别的文件当成原来的文件接上。宁可显示"找不到文件"。
- 主进程被卡住：网络盘、拔掉的 U 盘不能让界面没响应。
- 自动接上时打断正在放的歌，或者让壁纸、视频特效闪一下重新加载。

## 做法

考虑过三种：

1. **记住文件编号，自动找回（选了）**。NTFS 上每个文件有固定编号，同一个盘里移动、改名都不变。记下 `fs.stat` 的 `dev`（卷序列号）和 `ino`（文件编号），找不到时用 kernel32 的 `OpenFileById` + `GetFinalPathNameByHandleW` 查出现在的路径。2026-11-20 在本机用 koffi 实测过：普通用户权限就行，文件移动加改名以后能查到。不多占硬盘，深度图不用重算。
2. **导入时复制一份到数据目录**（没选）。最稳，但占两份硬盘（视频壁纸、整张专辑可能好几 GB），删了原文件也不释放空间，升级后要把已有的全复制一遍，往歌单里加歌要等复制完。用户选了方案一。
3. **只做手动"重新找"**（不单独用）。每次都要用户自己点。作为方案一自动找不回时的补充保留。

## 设计

### 记编号

- 新文件 `userData/file_ids.json`：`{ [规范化路径]: { path, vol, id, size } }`。规范化路径和 `shared/my-wallpapers.js` 的 `samePath` 规则一样（小写、斜杠统一成 `\`）。`vol` 是 `dev` 的十六进制，`id` 是 `ino`（用 `bigint: true` 取，存成十进制字符串，避免丢精度），`size` 是字节数。不放进 `config.json`：窗口用不到，不用跟着广播。
- 什么时候记：启动扫描时，以及每次保存配置之后（只处理还没记过的路径，加去抖）。路径还在、但编号和记录的不一样（原位置换成了别的文件）就更新记录。
- 不记：网络路径（`\\` 开头，或者盘符是网络盘）、安装目录 / `resources` 里的文件、userData 里的文件。
- 配置里已经不引用的路径从记录里删掉。

### 找回一个文件（`locate`）

1. 用原路径的盘符根目录打开卷（`CreateFileW`，带 `FILE_FLAG_BACKUP_SEMANTICS`），先确认根目录的 `dev` 和记录的 `vol` 一样，不一样就算找不到（盘符换了别的盘）。
2. `OpenFileById`（访问权限只要 `FILE_READ_ATTRIBUTES`）→ `GetFinalPathNameByHandleW` → 去掉开头的 `\\?\`；结果是 `\\?\UNC\...` 的当找不到。
3. 全部满足才算找到：
   - 路径里没有 `$Recycle.Bin` 这一层；
   - 还是同一类文件（图片 / 视频 / 音频，按扩展名，用现有的扩展名列表）；
   - 大小和记录的一样；
   - 对新路径 `stat` 出来的 `dev` + `ino` 和记录的一样。
4. 任何一步出错都当找不到，不抛异常。句柄都要关。

### 扫描

一个函数，三个时机：

- **启动时**：放在 `main.js` 现有的旧路径迁移之后、建窗口之前，同步跑一次。壁纸窗口一打开拿到的就是新路径，不会先退回 `background.png` 再提示"找不到上次的壁纸"。
- **设置窗口获得焦点时**：用户可能在软件开着的时候整理了文件夹。
- **每 60 秒一次**：设置窗口没打开时也能接上（唱片机、视频特效）。

定时和焦点时的存在判断用异步的 `fs.promises.access`。网络路径本来就不记编号，扫描不碰它们。

扫描时：路径在的，顺手补记编号；路径不在、有编号的，调 `locate`；找到的收集成 `[{ from, to }]`，一次处理（异步检查期间配置可能被改过，所以换路径要对处理那一刻的最新配置做）：

1. 用纯函数 `replacePaths(config, moves)`（放在 `shared/`，有单元测试）换掉配置里所有引用，返回要保存的部分配置。
2. 深度图缓存改 key：深度图文件改名成新 key 的文件名，更新索引里的 key、`imagePath`、`depthFile`，重写卸载清单。缓存现有的"大小 + 修改时间"检查不受影响（同盘移动不改修改时间）。
3. 编号记录改 key。
4. 保存配置，给两个窗口发 `files:relocated`（`[{ from, to }]`），再 `broadcastConfig()`。
5. 日志记一行（从哪到哪）。不弹提示：用户要的就是感觉不到。

### 跟着改的地方

- `currentVideo.imageAtTime`：`currentImage` 换了它也要换，否则 `resolveCurrent` 会以为"旧版本之后换过图片"，把当前视频清掉。
- 歌单每首的 `name`：等于旧文件名去掉扩展名（`trackName` 的规则）时换成新文件名；`videoOverlay.customName`：等于旧文件名（带扩展名）时换成新的。用户看到的名字和文件名一致。
- 壁纸窗口：背景壁纸只在 `wallpaper:show` 时换，配置里路径变了不会重新加载（`renderer/main.js` 只对 weather / vinyl / videoOverlay / customElements 几段做差异应用，已确认）。
- 唱片机：正在放的那首路径变了，不能从头重放。收到 `files:relocated` 时先把记着的当前路径换成新路径，之后的配置变化就不会触发重新加载。
- 视频特效：同样先换掉记着的路径，不重新加载视频。
- 设置页：选中的那一格、各页面记着的路径（壁纸页选中的壁纸、特效页的 `customVideoPath` 等）收到 `files:relocated` 后跟着换。
- 唱片机放一首歌失败时，先问主进程（新 IPC `files:locate`，只找这一首），找到了就换路径接着放，找不到再按现在的逻辑提示并跳到下一首。

### 手动接上

- 「我的壁纸」里找不到文件的格子：现在点了只提示一句，改成弹出选文件对话框，只能选同一类（图片 / 视频），标题"找到「文件名」现在的位置"。右上角 × 移除照旧。
- 歌单里找不到的歌：点那一行弹出选音频对话框。
- 视频特效：自己的视频找不到时，在文件名那里显示"找不到文件"；用现有的"选择视频"按钮重选，不另加按钮。
- 封面：只有自动找回和下面的顺带接上，不另加界面（找不到时唱片机显示默认封面，现在就是这样）。

接上一个（主进程新 IPC `files:relink { from, to }`）之后：

1. 和自动找回一样换掉所有引用、深度图缓存改 key、更新编号记录。
2. 顺带接上：`from` 所在文件夹记为旧文件夹，`to` 所在文件夹记为新文件夹。配置里其它找不到的路径，凡是在旧文件夹下面的，按相对位置到新文件夹下面去看，文件在而且是同一类就也接上。这里不比大小：用户已经确认过新文件夹是对的。
3. 壁纸重新生成缩略图（用户选的可能不是原来那个文件）。深度图缓存改 key 之后，现有的大小 + 修改时间检查会判断还能不能用，不能用就照常重新生成。
4. 如果是桌面上正在用的壁纸，马上重新应用（和改裁剪时的例外一样）。
5. 状态栏提示"已找回"，顺带接上了别的就说"另外还找回了 N 个"。
6. 选的文件已经在「我的壁纸」里（另一格）：提示"这个文件已经在「我的壁纸」里了"，不接。

### 测试

- 纯函数单元测试：`replacePaths`（每个字段、大小写和斜杠写法、`imageAtTime`、名字规则、没变的段不出现在结果里）、顺带接上的路径换算、从配置里收集所有路径。
- 找回模块（Node 测试，调 koffi）：临时目录里建文件 → 记编号 → 改名 / 挪到别的子文件夹 → 能找到；删掉 → 找不到；挪进名为 `$Recycle.Bin` 的文件夹 → 找不到；挪走后改了大小 → 找不到。
- 实机（按 PROJECT_NOTES 里真实应用的测试做法，用单独的数据目录）：挪动、改名当前的图片壁纸和视频壁纸后重启；软件开着时挪「我的壁纸」里的文件，再切回设置窗口；挪歌单里的歌和正在放的歌；挪到别的盘后手动接上，同一个文件夹里的顺带接上；当前壁纸手动接上后桌面恢复。
