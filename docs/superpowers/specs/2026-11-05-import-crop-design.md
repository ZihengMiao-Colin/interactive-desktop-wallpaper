# 导入时裁剪 — 设计

> 2026-11-05。现在用户自己的图片壁纸、视频壁纸和解锁视频都是程序自动居中裁切，用户管不了留下哪一部分。这份文档定下导入时手动裁剪的做法。裁剪窗口的样子是看过两个可以拖动的示意图后选定的（设置窗口弹框，没选全屏拖画面）。

## 为什么做

- 网上下载的图片经常在角落里带水印，用户想把它裁掉。
- 用户可以先用别的软件裁好再导入，但有人不会用，也有人不知道自己屏幕是什么比例，裁出来还是会被程序再裁一次。
- 所以裁剪要放在壁纸软件里，比例由软件算好，用户只管"留下哪一块"。

## 目标

1. 导入图片壁纸、视频壁纸和解锁视频时弹出裁剪框，用户拖框决定留下哪一块。
2. 框的比例固定是屏幕比例，用户不需要知道比例是多少。
3. 框默认放在现在自动裁切的位置。不想裁的人直接点"确定"，静止时的画面和现在一样。
4. 裁掉的部分在任何时候都不会出现在桌面上，包括鼠标移动时的视差和整体平移。
5. 已经导入的壁纸和解锁视频也能重新裁，包括这个功能出现之前导入的。
6. 改裁剪不需要重新生成深度图。

## 不做

- 元素页的贴纸素材、默认壁纸、全屏视频特效的自定义视频、唱片机封面。
- 托盘"更换壁纸"不弹框，之后可以在「我的壁纸」里再裁。
- 框超出图片、留黑边。竖图放到横屏上只能选其中一段，不能完整显示。
- 自由比例。比例始终跟屏幕走。
- 旋转、翻转、裁视频的时长。
- 生成裁好的新文件，或者改动用户的原文件。
- 安卓版不跟着做。

## 做出来也算失败的情况

- 鼠标移到屏幕角上，水印从边上滑进来（这是最严重的，功能等于白做）。
- 没动过裁剪的用户，壁纸看起来变了。默认壁纸和老用户的现有壁纸完全不受影响。
- 重启后裁剪丢了，水印又回来了。
- 摆放窗口里看到的位置和桌面上对不上。
- 用户不知道怎么退出裁剪框，或者取消后留下了半截导入的东西。

## 裁剪框

弹在设置窗口里（`<dialog>`，和卸载确认框同一套样式），背后的设置页变暗。

- 中间显示整张图，框里是亮的，框外变暗。框上有三分线和四个角点。
- 拖框内部移动，拖四个角点缩放。框不能超出图片，比例不变。
- 视频多一条时间滑块，用来换一帧看，因为水印可能只在某些画面里明显。不播放，也不出声。
- 底部一行：比例提示（"比例已按屏幕锁定 16:10"）、"恢复默认"、"取消"、"确定"。
- 框裁得比屏幕分辨率还小时，比例提示旁边多一句"可能会模糊"。只提示，不拦着。
- Enter 等于确定，Esc 等于取消。

"恢复默认"只是把框放回自动裁切的位置，要点"确定"才生效。

## 三个入口

**导入壁纸**：壁纸页"从电脑选择…" → 选文件 → 确认能读（现有的 `makeThumbnailInfo`）→ 弹裁剪框 → 确定后加入「我的壁纸」并选中，和现在一样往下走。点"取消"等于没导入，列表不变。如果这个文件已经在列表里，框打开时显示它原来的裁剪。

**重新裁剪壁纸**：鼠标放到「我的壁纸」的格子上，× 旁边多一个裁剪按钮。文件找不到时、生成深度图期间没有这个按钮。确定后缩略图换成裁好的样子；这个壁纸正被选中时，预览也跟着换。

**解锁视频**：解锁动画页选视频时同样先弹框。已有视频时多一个"重新裁剪"按钮，不用再导入一次。重新裁剪时打开的是复制到 `unlock_animation/` 里的那份视频，原文件挪走了也能裁。

## 实现要点

### 数据

裁剪区域 `{ x, y, w, h }`，都是相对原图的比例（0 ~ 1），左上角为原点。不存像素，这样换了分辨率、文件尺寸变了都还能用。

| 位置 | 字段 | 说明 |
|---|---|---|
| 「我的壁纸」条目 | `crop` | 没裁过的条目没有这个字段 |
| 当前视频 | `currentVideo.crop` | 和 `effect`、`sound` 一样，应用时抄一份 |
| 当前图片 | `currentImageCrop: { path, x, y, w, h }` | `currentImage` 必须保持字符串（旧版本会读它），所以另放。`path` 和 `currentImage` 对不上时不用，防止旧版本换过图片 |
| 解锁动画 | `unlockAnimation.crop` | |

当前壁纸另存一份，是因为用户可以把正在用的壁纸从「我的壁纸」移除，移除后桌面上的壁纸要继续保持裁剪，重启也一样。主进程 `applyWallpaper` 按路径从「我的壁纸」查 `crop` 再写配置、发给壁纸窗口，这样托盘换壁纸也用得上之前裁好的范围。列表里没有时看当前壁纸：壁纸刚被移除时还选中着，用户可以再点"应用壁纸"，这时裁剪不能丢（实测时发现的）。

注意这些地方都是白名单，新字段要加上，否则读配置时会被丢掉：`normalizeEntry`、`updateEntry`、`addEntry`、`resolveCurrent`、`applyPartial`、`unlock-animation.js` 的 `normalizeConfig`。

没有裁剪时 `resolveCurrent` 不带 `crop` 键，现有的对比和测试不用变。

### 纯逻辑：`shared/crop.js`（新文件，有单元测试）

- `normalizeCrop`：配置里读出来的值整理成合法区域，读不出来返回 `null`。
- `defaultCrop`：自动裁切的区域，也就是框的默认位置。
- `moveCrop`、`resizeCrop`：拖动和拖角点，比例不变，不超出图片。
- `fitCropToRatio`：框打开时屏幕比例和存的不一样（换了显示器），在原来的范围内收成新比例。
- 比例提示文字、"可能会模糊"的判断。

### 渲染：裁掉的部分不能滑进来

只改 Cover 映射不够。着色器现在把最后的取色位置限制在整张图内（`clamp(..., 0.001, 0.999)`），鼠标移动时会取到屏幕外的内容，水印就滑进来了。所以要做三件事：

1. **`Shared.parallax.cropCover`**：在裁剪区域内做 Cover 映射，没有裁剪时结果和 `coverTransform` 完全一样。屏幕比例和区域比例不一致时在区域内再裁，不会超出区域。
2. **取色限制在裁剪区域内**：`uCropMin` / `uCropMax` 替换写死的 `0.001` / `0.999`，背景着色器、元素着色器、设置页预览三处都要改。没有裁剪时值还是 `0.001` / `0.999`。光线步进算法不用动，所以 `rayMarchUV` 的 GLSL 和 JS 版本不受影响。
3. **视差手感不变**：视差位移是图片 UV 单位，裁得越小放大越多，同样的强度屏幕上动得越厉害。强度乘以缩放比例 `k = cropCover.scaleX / coverTransform.scaleX`（`Scene` 暴露出来，`renderer/main.js` 和设置页预览用）。元素的 `elementScreenShift` 除以 cover，缩放后在屏幕上的位移也一样。

整体平移：`panCover` 要在裁剪区域内留余量（`room` 按区域的宽高算），位移也用乘过 `k` 的强度，移到最边上也不会露出区域外面。

`Scene.load`、`Scene.loadVideo` 加 `crop` 参数，`updateCover` 改用 `cropCover`。摆放窗口走同一个 `resolveCurrent`，自动贴地和遮挡都经过 `getCover`，不用单独处理。

### 确定时总是记住框

点"确定"时即使框没动也记下来。否则水印刚好在自动裁切的范围外时，用户看到它被裁掉了，鼠标一动它又滑进来。没动过的框静止时和现在一样，只是视差时上下边不再露出框外的内容。

### 正在使用的壁纸

重新裁剪「使用中」的壁纸，点确定后桌面立刻更新，不用再点"应用壁纸"。这是例外：平时选中只是预览，但这里用户看到的是自己桌面上的水印，没变化会以为没成功。做法是确定后按当前壁纸再走一次 `api.applyWallpaper`，视频会从头放。

### 解锁视频

`resolvePlayback` 带上 `crop`，`player-window.js` 用查询参数传给播放页。播放页优先用 CSS `object-view-box: inset(...)`（Chromium 104 起支持，Electron 28 是 Chromium 120）配合现有的 `object-fit: cover`。要在真实窗口里确认对 `<video>` 有效，不行就换成外层容器加定位放大。

### 缩略图

`makeThumbnailInfo` 加 `crop` 参数，只画裁剪区域。`saveWallpaperThumb` 的文件名只看路径，重新裁剪后地址不变，浏览器会继续显示旧缩略图，所以要换文件名并删掉旧文件。解锁动画的缩略图同理。

### 新增接口

- `app:getScreenInfo`：主显示器的宽高和缩放比例（比例提示和模糊判断用）。
- `myWallpapers:add` 带 `crop`；新增 `myWallpapers:setCrop`（路径、区域、缩略图）。
- `unlock:setVideo` 带 `crop`；新增 `unlock:setCrop`；`unlock:getInfo` 返回视频地址，给裁剪框用。

新文件 `shared/crop.js`、`settings/crop-dialog.js` 要加进 `settings.html`、`index.html`、`renderer/unlock-player.html`（用到的才加）。`build.files` 已经包含 `shared/**`、`settings/**`。

## 已知限制（写进 PROJECT_NOTES）

- 视差时裁剪区域的四条边可能有一点拉伸：区域外的内容不能用，只能重复边上的像素。现在图片的左右边本来就这样，裁剪后四条边都可能出现。默认强度下最多十几像素。这是在"水印不能滑进来"和"边缘好看"之间选了前者，如果嫌明显，可以改成在区域内再放大一点。
- 深度图还是按整张图生成。裁得很小时，屏幕上用到的深度图分辨率变低，视差细节会少一些。
- 设置页的预览框比屏幕更扁，预览里看到的比实际桌面少一些，这一点和现在一样，裁剪框才是准的。没有 WebGL 时的预览不跟裁剪走（壁纸本身也要 WebGL，这个分支基本走不到）。

## 留给实现时决定

- 框的最小尺寸、角点大小、裁剪框的具体尺寸和布局（要放得进默认 960 宽的设置窗口）。
- 视频打开时默认显示哪一帧。
- 比例文字怎么写（能约分成小整数就写 `16:10`，不行就写 `1.60:1` 之类）。
- 键盘微调框的位置要不要做。

## 验证

单元测试：`shared/crop.js` 全部函数；`cropCover` 没有裁剪时和 `coverTransform` 一致；`panCover` 在裁剪区域内留够余量；白名单字段不丢；`currentImageCrop` 路径对不上时不用。

真实应用里要实测：

- 带水印的图，裁掉水印，视差强度拉到最大，鼠标移到四个角，水印不出现。
- 视频壁纸三种效果都一样。
- 重启后裁剪还在；把正在用的壁纸从「我的壁纸」移除再重启，裁剪也还在。
- 摆放窗口里元素的位置和桌面一致。
- 解锁动画预览和真实解锁都按裁好的画面放。
- 没裁过的壁纸和默认壁纸，画面和改之前一样。
