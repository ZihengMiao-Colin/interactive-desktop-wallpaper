# 诊断报告和问题反馈 — 设计

> 2026-11-18。软件在别人电脑上出问题时，开发者拿不到现场信息。用户同意按下面的判断直接做（"你提到的几点都可以添加进去……按照你的判断来干"）。

## 为什么做

- 报错其实早就记下来了：`electron-log` 把主进程和各窗口的控制台输出写进数据目录的 `logs/main.log`。缺的是**普通用户找不到这个文件，也不知道该发什么**。
- `tools/desktop-diagnose.bat` 能收集桌面层信息，但没打进安装包，别人拿不到。
- 很多问题根本不弹错误（壁纸盖住图标、白屏、点了没反应），所以入口要能随时手动点，不能只在报错时出现。

## 目标

1. 用户一键生成一份**诊断报告**（一个 txt），放在桌面上，可以直接用微信、QQ 发给开发者。
2. 用户也可以**到 GitHub 反馈**：先生成报告，再打开新建 issue 页面，标题和基本信息已经填好，把 txt 拖进去就行。
3. 入口三处：设置页"设置"→"问题反馈"、托盘菜单"问题反馈"（设置窗口打不开时用）、主进程出错时的中文提示框。
4. 补记现在漏掉的崩溃：窗口进程退出（`render-process-gone`）、GPU 等子进程退出（`child-process-gone`）、窗口没响应（`unresponsive`）。
5. 主进程出错时，原来弹的英文框（electron-log 默认的 "A JavaScript error occurred in the browser process"）换成中文提示框，带"生成诊断报告"按钮。
6. 路径里的 Windows 用户名在报告里换成 `<用户名>`。

## 不做

- 自动上传报告、自己架服务器收报告（要服务器，也有隐私问题）。
- 崩溃后自动重开窗口（是行为上的改动，不属于"诊断"，以后可以单独做）。
- Chromium 的原生崩溃转储（`crashReporter` 的 minidump）：文件大、要符号文件才看得懂，现阶段用不上。
- 程序完全打不开（还没跑到 JS）的情况：这时只能手动发 `%APPDATA%\interactive-desktop-wallpaper\logs\main.log`，README 里写清楚。

## 做出来也算失败的情况

- 生成报告这一步自己出错、什么都没生成（任何一部分收集失败都只在报告里写一行"读取失败"，其余照常）。
- 报错提示框一直弹（同一个错误在定时器里反复出现）。
- 报告里出现完整的 Windows 用户名。
- 生成报告时启动 PowerShell 等外部程序（360 会拦本程序启动 PowerShell，见 PROJECT_NOTES 第 33 项附近），全部在进程内完成。

## 方案

考虑过三种做法：

1. **把 `tools/desktop-diagnose.ps1` 打进安装包，按钮去跑它**：现成，但要启动 PowerShell，正好是 360 会拦的；而且它读的是固定的 `%APPDATA%` 路径。不选。
2. **只做"打开日志文件夹"按钮**：最省事，但用户还得自己找文件、发什么也不清楚，系统和显卡信息也没有。不够。
3. **主进程里收集信息、拼成 txt（选这个）**：版本、系统、显示器、显卡、桌面层状态、配置、可能有关的其他软件（koffi 列进程，不启动外部程序）、最近的错误、日志最后一段。全部在进程内完成。

## 报告内容

文件名 `互动3D壁纸-诊断报告-<年月日-时分秒>.txt`，UTF-8 带 BOM、CRLF 换行（老版本记事本也能正常显示中文）。放在桌面，桌面写不进去时放"下载"，再不行放数据目录。生成后在资源管理器里选中它。

1. 开头说明：生成时间；路径里的用户名已去掉；文件名（壁纸、音乐）没去掉，介意可以先删掉再发。
2. 基本信息：软件版本、安装版 / 开发版、Electron / Chrome / Node 版本、系统版本和架构、语言、已运行多久、安装位置、数据目录、深度图目录、这次是不是开机自启的。
3. 显示器：每块屏的分辨率（物理像素和 DIP）、缩放、位置，哪块是主屏。
4. 显卡：硬件加速状态（`app.getGPUFeatureStatus()`）、显卡列表和驱动版本、OpenGL 渲染器（`app.getGPUInfo('complete')`，超时退回 `basic`）。
5. 壁纸状态：挂没挂到桌面层、壁纸窗口的父窗口和样式（koffi）、暂停原因（全屏 / 锁屏 / 睡眠 / 摆放）。
6. 可能有关的其他软件：只列命中已知名单的进程（360、腾讯电脑管家、火绒、金山毒霸，以及 Wallpaper Engine、Lively、Rainmeter 等壁纸 / 桌面美化软件），不列全部进程。
7. 最近的问题：日志里最后 30 条 `[error]` / `[warn]`（去掉 Electron 开发时的安全警告）。
8. 配置：`config.json` 的内容。
9. 日志：`main.log` 最后 1500 行（不够时从 `main.old.log` 补）。

## GitHub 反馈

打开 `https://github.com/ZihengMiao-Colin/interactive-desktop-wallpaper/issues/new?title=…&body=…`。正文：问题描述（让用户自己填）、"把桌面上的 xxx.txt 拖到这里"、自动填好的基本信息（版本、系统、显示器、显卡、桌面层、可能有关的软件、最近 5 条错误）。整个地址控制在 6000 字符以内，超了就少放几条错误。按钮旁边写明：需要 GitHub 账号，内容所有人都能看到。

## 报错提示框

- 只对主进程的未捕获异常弹（Promise 未处理的 rejection 只记日志，和 electron-log 原来的规则一样）。启动流程 `startApp` 出错单独接住，也弹（这时托盘可能还没有，按钮是"生成诊断报告" / "退出程序"）。
- 同一时间只弹一个；带"本次运行不再提示"勾选框；两次之间至少隔 10 分钟。
- 按钮：生成诊断报告 / 忽略 / 退出程序。

## 实现时的调整

- 显卡信息的超时从 5 秒改成 15 秒：实测每次运行第一次 `getGPUInfo('complete')` 就要 5 秒。
- 主显示器的物理分辨率问系统（win32 `getScreenSize`）：Electron 的 `dipToScreenRect` 会把 2560 算成 2561。报告里加了刷新率。
- 页面的控制台输出改成自己记（`watchRendererConsole`，替代 electron-log 的 `spyRendererConsole`），错误和警告带文件名和行号。原来想在 preload 里监听 `error`，但开着 contextIsolation 时 preload 收不到页面脚本的异常。
- GitHub 正文不写"桌面上的"：桌面写不进去时报告在"下载"里。
