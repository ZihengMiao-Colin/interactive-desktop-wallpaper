# 唱片机：每首歌一张封面 + 进度条拖动

日期：2026-11-20

## 为什么做

- 现在整个唱片机只有一张封面，换歌时唱片中间的图不变。用户要每首歌有自己的封面，切歌时跟着换。
- 设置页的唱片机卡片只能播放 / 暂停 / 切歌，不能跳到歌的某个位置。用户要在这一页加能拖的进度条。

## 用户定的

- 歌曲文件里自带封面时，默认直接用自带的。
- 软件本身不带默认封面图和歌曲（装好后歌单是空的，没有任何封面图片）。
- 其他细节由助手决定（下面标"助手定的"）。

## 不做

- 不带任何默认封面图片和示例歌曲。
- 不读文件夹里的 `cover.jpg` / `folder.jpg` 这类整张专辑共用的图（歌单里常混着不同专辑，会配错）。
- 不读 ogg、wav 里的封面（很少有，格式也麻烦）；aac 开头带 ID3 标签的能读到。
- 播放进度不存进配置，重启后还是从头放（和现在一样）。

## 做法比较（助手定的）

读自带封面：

| 做法 | 取舍 |
| --- | --- |
| **自己写一个小解析器（选这个）** | 只认 mp3（ID3v2.2 / 2.3 / 2.4）、flac、m4a / mp4 三种，几百行加单元测试，不加依赖 |
| 用 `music-metadata` 包 | 格式最全，但要多装十几个依赖包，新版本是 ESM，主进程要另外处理 |
| 调用 ffmpeg | 用户电脑上一般没有 ffmpeg，不可行 |

读出来的封面：**存成缓存文件（选这个）**，壁纸和设置页都按普通图片路径用；不选"每次读成 data URL"，歌单长时设置页每行一张大图，内存占得多。

进度条的进度：**壁纸主动推给设置页（选这个）**；不选"设置页定时问壁纸"，那要跨两个窗口一问一答，更复杂。

## 封面

### 数据

- 歌单里每首歌多一个可选字段 `cover`：用户给这首歌选的图片路径。`normalizeVinyl` 要保留它（现在会把多出来的字段丢掉）。
- 去掉整台唱片机共用的 `coverPath`（读配置时丢弃，默认值里也删掉）。旧版设过的封面图片文件本身不动，只是不再用；想用的话可以给某首歌重新选上（助手定的：用户说了自带封面优先，旧封面如果套到每首歌上会盖住自带的）。

### 一首歌显示哪张图（按顺序找，找到就停）

1. 用户给这首歌选的图（`cover`），文件还在。
2. 歌曲文件自带的封面。有好几张时优先"封面（front cover）"那张，没有就用第一张。
3. 和歌在同一个文件夹、文件名相同的图片：`秋绪.mp3` 配 `秋绪.jpg` / `.jpeg` / `.png` / `.webp`（助手定的：很多下载工具这样存封面，测试素材也是这样放的）。
4. 都没有：唱片中间显示现在的纯色标签（页面里画的，不是图片文件）。

### 读自带封面

- 放在主进程（新模块，比如 `src/audio-cover.js`）。按文件开头的字节认格式，不看扩展名（测试素材就是改了扩展名的 mp4）：
  - `ID3` 开头：读 ID3v2 标签里的 `APIC`（2.2 是 `PIC`），处理 2.4 的 syncsafe 长度和反同步。
  - `fLaC` 开头：读 `PICTURE` 元数据块。
  - mp4 / m4a：按盒子往下找 `moov > udta > meta > ilst > covr > data`，`moov` 在文件末尾也能找到（只读盒子头，不读整个文件）。
- 读出的图片写到数据目录下的 `vinyl_covers/`，文件名由"歌的路径 + 修改时间 + 大小"算出来，歌文件改了会重新读。同一首歌只解析一次（内存里也记一下）。
- 启动时清掉不属于当前歌单里任何一首的缓存文件。
- 解析出错、文件读不到：当作没有自带封面，不报错。
- IPC：`vinyl:resolveCover`（设置页、壁纸都用），传 `{ path, cover }`，返回 `{ file, source }`，`source` 是 `manual` / `embedded` / `sidecar` / `none`。

### 壁纸上

- 换歌时按上面的顺序找封面，换到唱片中间。异步找，找回来时如果已经又换了歌就丢掉结果。
- 摆放窗口里也显示当前这首的封面。

### 设置页（唱片机页）

- 卡片里转的那张唱片显示当前这首的封面。
- 歌单每一行加一个小封面（序号和歌名之间）。点小封面给这首换图（不会顺带播放这首），悬停提示"给这首歌换封面"。
- "唱片封面"一行改成管当前这首：说明写"「秋绪」：文件自带的封面 / 同名图片 / 你选的图 / 没有封面"，按钮"更换…"，以及在用自选图时出现的"不用这张"（去掉自选图，回到自带的或同名的，都没有就是纯色标签）。
- 封面结果在设置页里记一份，配置广播重画歌单时不重复去问主进程（换了图、歌文件变了才重新问）。

## 进度条

### 样子（设置页唱片机卡片）

```
[唱片]  CURRENT TRACK                       [上一首] [▶] [下一首]
        秋绪
        正在播放 · 第 2 / 2 首
        1:23 ━━━━━━━━━●──────────────── 4:05
```

进度条在歌名和状态下面，和文字左对齐，右边到卡片的按钮区之前（助手定的；窗口窄时以不出现横向滚动条为准，具体宽度实现时调）。

### 行为

- 拖动时左边的时间跟着变，松手才跳；拖的时候不被壁纸发来的进度打断。键盘方向键也能调（range 自带）。
- 播放中跳：声音马上跳过去，唱臂抬起、摆到对应那一圈再放下，声音不停（助手定的：等唱臂放下再出声会慢一秒，拖进度条的人想马上听到）。
- 唱臂正在从停靠位摆进来（还没开始放）时跳：重新算目标，唱臂直接摆到新位置。
- 暂停时跳：只改位置，唱臂留在停靠位；下次播放时唱臂落到新位置。
- 顺序播放放完停下后跳：从那个位置开始，按播放接着放。
- 没有歌、壁纸还没读出时长、壁纸窗口不在：进度条不能拖，两边显示 `--:--`。
- 换歌时进度回到 0。

### 通信

- 壁纸 → 设置页 `vinyl:progress`：`{ path, currentTime, duration, playing }`。在 `timeupdate`（Chromium 大约每 0.25 秒一次）、`durationchange`、`seeked`、`play`、`pause`、换歌时发。主进程只在设置窗口存在且显示着时转发。
- 设置页 → 壁纸 `vinyl:requestProgress`：设置页打开或切到唱片机页时要一次当前进度。
- 设置页 → 壁纸 `vinyl:seek`：`{ path, time }`。`path` 和壁纸当前这首对不上就不跳（防止刚切歌时跳错歌）。
- 设置页收到进度后不要求每帧动画，0.25 秒一跳够用（助手定的）。

## 测试

- 单元测试：封面解析（手工拼 ID3v2.2 / 2.3 / 2.4、flac、mp4 盒子的字节，包括 `moov` 在后面、多张图选封面、坏数据）、找封面的优先顺序、`normalizeVinyl` 保留 `cover` 和丢掉 `coverPath`、秒数格式化。
- 真实应用里测（单独的数据目录）：用 `壁纸素材/唱片机/` 里的两首（其实是改了扩展名的 mp4，没有自带封面，旁边有同名图片），再用 ffmpeg 做几份带自带封面的 mp3 / flac / m4a 副本；验证切歌换封面、选图 / 不用这张、拖进度条（播放中 / 暂停 / 刚切歌）、唱臂动作、820×560 没有横向滚动条。
